# Meu site de portfólio

> Protótipo: isto é um teste da Itera, ainda não é um produto.

## O que você vai construir

Um site só seu, sobre você e seus projetos, que qualquer pessoa pode abrir
pelo celular. Você escreve tudo em 3 arquivos:

- `index.html`: o que aparece na página (textos, links, imagens)
- `style.css`: como a página fica bonita
- `script.js`: o que acontece quando alguém clica

## Como enviar: editar e salvar no GitHub

O GitHub guarda seus arquivos. Para mudar um arquivo e salvar, siga estes cliques:

1. Na página do modelo, clique no botão verde **Use this template** e depois em **Create a new repository**.
2. Em **Repository name**, escreva um nome para o seu site (por exemplo `meu-portfolio`).
3. Marque **Public**. O repositório precisa ser público para a Itera conseguir ler o resultado.
4. Clique em **Create repository**. Esta é a sua cópia do projeto.
5. Dentro do repositório, clique no nome do arquivo que quer mudar (por exemplo `index.html`).
6. Clique no ícone de **lápis** no canto direito ("Edit this file") e escreva a sua mudança.
7. Clique no botão verde **Commit changes...** e, na janelinha, clique de novo em **Commit changes**.
   Isso salva a mudança no GitHub.
8. Espere cerca de 1 minuto. Para ver o resultado, abra a aba **Actions** do repositório
   ou volte na página do projeto na Itera e toque em **Atualizar**.

Cada vez que você salva, um robô confere o seu site.

## Os 5 passos

1. **Estrutura**: monte o esqueleto da página no `index.html`.
2. **Conteúdo**: escreva sobre você, com uma lista, um link e uma imagem.
3. **Estilo**: ligue o `style.css`, mude uma cor, dê espaço, ponha itens em fila e ajuste para o celular.
4. **Interação**: faça um botão que muda algo na página quando alguém clica.
5. **Publicar**: coloque o site no ar com o GitHub Pages.

Dentro dos arquivos tem comentários `TODO` dizendo o que fazer em cada passo.

## Como ver se você acertou

1. Abra a página do projeto na Itera e cole o endereço do seu repositório.
2. Cada passo mostra se está feito. Se algo faltou, a página diz o que falta e
   mostra um link para a lição certa.
3. Também dá para ver no GitHub: aba **Actions**, depois a rodada mais recente (a primeira da lista).
   Nos itens `step-1` a `step-5`, verde quer dizer certo e vermelho quer dizer que falta algo.

O robô diz **o que falta**, nunca a resposta pronta. Isso faz parte de aprender.

## Passo 5: ligar o GitHub Pages

1. No seu repositório, clique em **Settings** e depois, no menu da esquerda, em **Pages**.
2. Em **Source**, escolha **GitHub Actions**.
3. Salve uma mudança qualquer (veja "Como enviar", passos 5 a 7).
4. Em cerca de 2 minutos o site fica no ar em
   `https://SEU-USUARIO.github.io/NOME-DO-REPOSITORIO/`.
   O robô confere o passo 5 de novo quando o site termina de subir.
